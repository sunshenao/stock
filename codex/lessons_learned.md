# 核心经验

选股前读取。以下规则只记录容易重复犯的错误，具体执行以 `CLAUDE.md` 和 `scripts/risk_rules.py` 为准。

1. **固定的是ETF池，不是主线。** 每次周度选择必须全量扫描 `etf.txt`，用户观点、旧持仓和上周赢家不自动加分。
2. **正式换仓按周，不按日。** 日度排名波动大，只允许止损、催化证伪、冰点降仓和大簇崩盘处理。
3. **催化必须面向未来。** 已发生利好只能解释涨幅；新仓需要未来1至6周的待发生事件和明确反证。
4. **趋势未坏不要机械止盈。** 短期排名下降不等于卖点，老持仓采用延续缓冲和移动止损。
5. **板块宽度不能重复计票。** 多只同主题ETF按一个方向计算，防止虚假扩散。
6. **池内没有代表标的就报告缺口。** 不得自行添加ETF，也不得用池外个股替代正式推荐。
7. **市场状态先于选股。** 总仓位由全A宽度、成交额、涨跌停和指数趋势决定，不能由想买的标的倒推。
8. **信号和成交必须错开。** 盘后信号下一交易日开盘执行，ATR和排名只使用信号日以前数据。
9. **评价净收益而不是命中率。** 同时比较超额、回撤、换手、成本和样本外稳定性。
10. **弱中期趋势需要强反转证据。** 非防守新仓的60日趋势为负时，普通短线反弹不够，核心仓需要分数与20日动量共同确认。
11. **相关性约束要服从市场状态。** 震荡和退潮限制同风险簇新仓，主升期允许集中，旧强仓不能只因同簇被卖掉。
12. **新闻是风险层，不是选股发动机。** 单一媒体标题最多黄色，红色需要多源或系统性硬事件；利好不能抵消利空，也不能单独制造买点。

## 已验证案例

| 问题 | 结论 |
|---|---|
| 白银强趋势被过早卖出 | 周度延续与移动止损优于每日换排名 |
| 2026-07科技多细分同步下跌 | 大簇风险必须按独立细分方向识别 |
| 冰点后单日暴力反转次日失败 | 非冰点状态需要连续确认 |
| 两只、三只和多套仓位并存 | 标的数量和仓位只能由 `risk_rules.py` 定义 |
| 日度回放换手和回撤过高 | 周度正式选择，日度仅风控 |
| 2026-W20弱中期趋势反抽失败 | 核心新仓增加60日趋势/强反转门槛 |
| 2026-W22成长方向共振下跌 | 周初信号无法完全识别，必须保留日度大簇崩盘风控 |
| 2026-W27同风险簇集中 | 非主升最多新开2只同簇，第三只优先低相关补位 |
